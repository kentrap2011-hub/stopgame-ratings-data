**Важно о доказательствах:** наличие файлов в GitHub, их байтовая идентичность и коммиты проверены. Однако Git-коммит *не хранит* вызовы инструментов, доставивших байты из контейнера в GitHub. Поэтому описанная ниже последовательность — **воспроизводимый технический алгоритм**, а не дословная запись вызовов прежнего чата. Не заявляй, что определённый канал передачи контейнер → GitHub уже работает в любом чате; проверь это в текущей среде.

## Рабочая последовательность для нового изображения

1. Открой `main` и `gh-pages`, проверь актуальные SHA голов обеих веток. Посмотри существующую отдельную папку примерки и её `index.html`, `styles.css`, `script.js`. **Не переписывай корневой сайт, `steam-profile-preview/`, старые проекты и чужие файлы.**
2. Найди исходный PNG в текущих вложениях или ChatGPT Library через `files.list` / `files.search`. Возьми **реальный file_id**. Вызови `files.materialize` с `representation="raw_file"`, а не `text`. Пользовательские файлы из текущей беседы могут быть уже смонтированы в `/mnt/data`.
3. В Python/контейнере проверь сигнатуру PNG, размеры, число байтов, **SHA-256** и **Git blob SHA**. Не пользуйся скриншотом, картинкой из превью, Pillow.save(), конвертацией в WebP и пересжатием. Пример кода:

```python
from pathlib import Path
import hashlib, base64
p = Path("/mnt/data/исходный.png")
data = p.read_bytes()
assert data.startswith(b"\x89PNG\r\n\x1a\n")
sha256 = hashlib.sha256(data).hexdigest()
git_sha = hashlib.sha1(b"blob " + str(len(data)).encode() + b"\0" + data).hexdigest()
blob_base64 = base64.b64encode(data).decode("ascii")
print(len(data), sha256, git_sha)
# blob_base64 передать в разрешённый бинарный канал записи GitHub, НЕ в HTML
```

4. Перенеси **исходные байты** в GitHub. Если доступны GitHub Git Database действия и реальный мост для передачи данных, используй `create_blob(content=<base64>, encoding="base64")` отдельно для каждого PNG. Затем `create_tree(base_tree_sha=<текущий tree gh-pages>, tree_elements=[...])`, `create_commit(parent_sha=<текущий head gh-pages>, tree_sha=...)` и `update_ref(branch_name="gh-pages", expected_sha=<старый head>)` без force. В записи дерева для PNG нужны `mode:"100644"`, `type:"blob"`, `sha:<полученный blob SHA>`, `path:"новая-папка/images/....png"`. Если доступен авторизованный Git CLI/браузер с доступом к исходным файлам, можно вместо этого сделать обычный add/commit/push только новой папки.
5. **Критический момент:** `files.materialize` обеспечивает доступ контейнера к файлам, но *сам по себе не передаёт* содержимое в инструмент GitHub. Если GitHub-коннектор не читает контейнер, а контейнер не имеет сетевых полномочий, эти части не соединяются автоматически. Не пытайся заменить оригиналы заглушками, ссылками `sandbox:` или приватными `file_id`. Не выдавай публикацию за завершённую, пока нет реальных бинарных объектов в `gh-pages`.
6. Перед записью страничного HTML проверь наличие всех оригинальных PNG в GitHub. Добавь страницу **только в новой отдельной папке** ветки `gh-pages`; изображения подключай относительными путями `./images/имя.png`, `object-fit:contain`, без обрезки и перерисовки. Для `SS_Landscape` можно переиспользовать внешний адрес Steam CDN из старой примерки (проверить его текущую доступность).
7. После записи получи через GitHub содержимое папки `images/` и сверяй **Git blob SHA** каждого файла с рассчитанным локально значением. Проверь, что SHA коммита `gh-pages` изменился, и его diff затрагивает только новую папку. Проверяй публичные URL страницы и каждого PNG, если инструмент браузера позволяет; невозможность проверки HTTP отмечай как **NOT VERIFIED**, а не как PASS.
8. Отчёт о коммите, прямых URL, размерах, контрольных суммах, проверках и ограничениях записывай **в `main`**, отдельно от страницы. Проверяй оба результата повторным GitHub-чтением.

## Что не путать с этой задачей

Старые workflows `.github/workflows/cache-sifu-artwork.yml` и `render-sifu-artwork-once.yml` действительно сохраняли медиа в `gh-pages` через GitHub Actions. Но первый скачивал **публичные изображения сторонних сайтов** и переводил их в WebP, а второй вырезал/кодировал видео из **публичного трейлера**. **Это не готовый путь для трёх приватных исходных PNG из ChatGPT Library.** Для требования побайтовой идентичности их нельзя переиспользовать без существенной переделки.

**Статус примера на 2026-11-03:** GitHub-файлы и SHA подтверждены; внешний HTTP и тест на настоящем Android из среды публикации не подтверждены. Проверяй при следующем запуске.
